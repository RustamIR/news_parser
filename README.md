# Новостной парсер в Telegram

Бот на **aiogram 3** следит за телеграм-каналами и новостными сайтами и присылает
не всю ленту, а только то, что попадает в заданные вами темы — с коротким
пересказом каждой новости.

Три готовые рубрики: 🛡 информационная безопасность, 📈 финансы, 🌍 геополитика.
У каждой свой набор источников, тем, интервал опроса и порог отсечки. Рубрику
можно добавить свою прямо из бота.

## Как достигается выборочность

```
источники → предфильтр по темам → анализ моделью → порог → вам в чат
  30 постов        19 отброшено       11 постов     оценка ≥ порога
```

1. **Сбор.** Telethon читает телеграм-каналы, aiohttp — RSS-ленты и обычные
   HTML-страницы. Дубли отсекаются по хэшу ссылки/id сообщения.
2. **Предфильтр** (`app/analysis/prefilter.py`). Пост сверяется с ключевыми и
   стоп-словами ваших тем. Не задел ни одну тему — помечается `skipped` и дальше
   не идёт. Это бесплатно и снимает основную массу шума.
3. **Анализ** (`app/analysis/`). Только уцелевшие посты уходят в модель: она
   ставит релевантность 0–100 и пишет резюме в 2–3 предложения. Реклама и
   анонсы, проскочившие по ключевым словам, отсекаются здесь.
4. **Отправка.** Всё, что набрало не меньше порога рубрики, приходит подписчикам
   сразу или копится в дайджест.

Шаг 3 можно не подключать вовсе — тогда оценка берётся из предфильтра, а резюме
собирается из первых предложений поста.

## Чем анализировать

Движок выбирается переменной `LLM_BACKEND`; при `auto` берётся первый доступный.

| `LLM_BACKEND` | Что делает | Стоимость | Скорость |
|---|---|---|---|
| `ollama` | локальная модель на вашей машине | бесплатно | ~5–8 с на пост |
| `claude` | Claude через API | по токенам | ~2–4 с на пост |
| `none` | без модели, только ключевые слова | бесплатно | мгновенно |
| `auto` | Ollama, если поднят; иначе Claude | — | — |

### Локальная модель (без ключей и оплаты)

```bash
brew install ollama && ollama serve
```

```bash
ollama pull qwen3:8b
```

Больше ничего делать не нужно: при `LLM_BACKEND=auto` бот сам найдёт Ollama на
`localhost:11434` и возьмёт модель из `OLLAMA_MODEL`.

Модель весит ~5 ГБ и держится в памяти 10 минут после последнего запроса
(`KEEP_ALIVE` в [app/analysis/ollama.py](app/analysis/ollama.py)). Поэтому первый
пост каждого прохода ждёт загрузку модели с диска, а остальные разбираются за
5–8 секунд. На M3 Pro проход из 10 постов, где 4 дошли до модели, занимает
около 30 секунд.

Локальный разбор режет текст поста до 2500 символов против 6000 у облака: решение
«по теме или нет» принимается по началу поста, а каждый лишний токен здесь —
это время. Качество на пограничных случаях ниже облачного: замаскированную
рекламу и иронию 8B-модель ловит хуже. Если нужна точность — ставьте
`LLM_BACKEND=claude`.

### Claude через API

Нужен `ANTHROPIC_API_KEY` с [console.anthropic.com](https://console.anthropic.com)
и деньги на балансе (предоплата, минимум ~$5). Цены за 1 млн токенов: Opus 5 —
$5/$25, Sonnet 5 — $3/$15, Haiku 4.5 — $1/$5. Один разобранный пост обходится
примерно в 2,4 ¢ на Opus 5 и 0,5 ¢ на Haiku 4.5 — платите только за посты,
прошедшие предфильтр.

Если баланс кончится или ключ отзовут, бот один раз напишет об этом в лог,
выключит движок до перезапуска и продолжит работать по ключевым словам — без
обречённых запросов на каждый пост.

## Установка

```bash
python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt
```

```bash
cp .env.example .env
```

Заполните `.env`:

| Переменная | Зачем | Где взять |
|---|---|---|
| `TELEGRAM_TOKEN` | сам бот | [@BotFather](https://t.me/BotFather) |
| `ADMIN_IDS` | кто может пользоваться ботом | [@userinfobot](https://t.me/userinfobot) |
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | чтение телеграм-каналов | [my.telegram.org](https://my.telegram.org) → API development tools |
| `LLM_BACKEND` | чем анализировать: `auto` / `ollama` / `claude` / `none` | см. «Чем анализировать» |
| `OLLAMA_MODEL` | модель для локального анализа | `ollama pull qwen3:8b` |
| `ANTHROPIC_API_KEY` | анализ через облако (опционально) | [console.anthropic.com](https://console.anthropic.com) |

> **`ADMIN_IDS` лучше заполнить.** Пустой список означает, что боту может писать
> кто угодно — включая расход вашего ключа Anthropic.

### Авторизация для чтения каналов

Bot API не даёт читать произвольные каналы — бот видит только те чаты, куда его
добавили админом. Поэтому чтение идёт от имени обычного аккаунта через Telethon:

```bash
python login_telegram.py
```

Скрипт спросит номер телефона, код из Telegram и пароль 2FA, после чего запишет
`TELEGRAM_SESSION` в `.env`. Строка сессии равносильна доступу к вашему
аккаунту — `.env` уже в `.gitignore`, не коммитьте его и никому не передавайте.

Шаг можно пропустить. Без Telethon бот читает сайты, RSS и открытые
телеграм-каналы через публичную витрину `t.me/s/…` — см. раздел «Каналы без
api_id» ниже. Недоступны останутся только закрытые каналы и чаты.

Если my.telegram.org отдаёт `ERROR` при создании приложения — это известная
болячка сайта, а не ваша ошибка. Обновите страницу и проверьте API development
tools: приложение часто создаётся несмотря на сообщение. Помогает также другой
браузер, режим инкогнито без расширений и заполненное поле Description.

### Запуск

```bash
python run.py
```

## Настройка сообщества

Бот рассчитан на схему «одна группа для управления + отдельный канал под каждую
тему». Читает он чужие каналы аккаунтом через Telethon, а Bot API использует
только чтобы принимать команды и публиковать результат.

```
ЧТЕНИЕ (чужие каналы)          ПУБЛИКАЦИЯ (ваше сообщество)
Telethon, ваш аккаунт          Bot API, @вашбот
        │                                 │
        ▼                                 ▼
  @source1, @source2 ──► фильтр ──►  канал «ИБ»
  RSS, сайты                         канал «Финансы»
                                     канал «Геополитика»
                                           ▲
                         группа NewsParser ┘ ← отсюда управляете
```

| Где | Роль | Что нужно боту |
|---|---|---|
| Группа `NewsParser` | приём форм и команд | участник, privacy mode выключен |
| Группы по темам | публикация отобранного | **просто участник** |
| Каналы по темам | публикация отобранного | администратор, право «Публикация сообщений» |
| Личка с ботом | то же приватно | — |

**Про чтение чужих каналов:** бот не должен быть админом нигде у источников и
вообще к ним не обращается — читает Telethon или витрина `t.me/s/`. Права нужны
только там, куда бот **пишет**.

Порядок сборки:

1. **Заполните `ADMIN_IDS`** своим ID (`/chatid` или [@userinfobot](https://t.me/userinfobot)).
   Без этого бот слушается кого угодно, а привязать каналы сможет любой прохожий.
2. **Выключите privacy mode**: [@BotFather](https://t.me/BotFather) → `/setprivacy` →
   выберите бота → **Disable**. Иначе бот не увидит в группе сообщения без команды
   и формы придётся слать только через `/add`.
3. **Добавьте бота в группу** сообщества и отправьте там `/bind` — группа станет
   управляющей, её админы получат право пополнять парсер.
4. **Задайте, куда публиковать каждую рубрику.** Два пути:

   **Без выдачи прав (проще).** Сделайте три группы по темам, добавьте бота
   участником и отправьте в каждой `/target <рубрика>`:

   ```
   /target infosec
   /target finance
   /target geopolitics
   ```

   Рубрику можно назвать и по-русски — `/target ИБ`, `/target финансы`.
   Отключить — `/target -` в том же чате. Работает и в личке, и в управляющей
   группе.

   **Отдельными каналами.** Добавьте бота админом с правом «Публикация
   сообщений», затем в личке `/start` → рубрика → **📢 Привязать канал** →
   перешлите пост из канала или пришлите `@юзернейм`. Админство тут
   обязательно: в каналы Telegram посторонним писать не даёт, обхода нет.

5. **Наполните формой** — см. ниже.

После этого каждая рубрика льётся в свой канал; подписки в личке (`🔔 Подписаться`)
продолжают работать параллельно.

## Форма пополнения

Основной способ добавления — одно сообщение в управляющую группу или в личку.
Пошаговый мастер тоже остался, но в группе он неудобен: несколько человек пишут
в один чат.

```
рубрика: ИБ
источники:
@dataleak
https://xakep.ru/feed/
https://www.anti-malware.ru/news
тема: Утечки данных
описание: подтверждённые утечки баз российских компаний, реакция регулятора
ключевые: утечка, слив базы, персональные данные, взлом*
стоп: вебинар, курс, скидка, розыгрыш
```

Порядок полей произвольный, заполнять всё не обязательно — можно прислать только
источники или только слова. Шаблон всегда доступен по `/form`.

* **рубрика** — обязательна, узнаётся по обрывку названия: `ИБ`, `иб`,
  `информационная`, `infosec`, `гео`, `финансы`.
* **источники** — списком, тип определяется сам; синонимы поля: `каналы`,
  `ресурсы`, `сайты`, `чаты`, `ленты`.
* **тема** — если такая уже есть, форма её **дополнит**, а не перезапишет. Когда
  тема не указана, а слова есть, они уйдут в единственную тему рубрики; если тем
  несколько, бот попросит уточнить.
* **ключевые** / **стоп** — правила те же, что в разделе про темы ниже.

Если privacy mode выключен, форму в управляющей группе можно слать без команды —
бот распознаёт её по строкам вида `рубрика:`. В остальных чатах он молчит.

## Работа с ботом

`/start` → рубрика → дальше всё кнопками.

**Источники** — пришлите по одному в строке, можно пачкой:

```
@breakingmash
https://habr.com/ru/rss/hub/infosecurity/
https://www.anti-malware.ru/news
```

Тип определяется автоматически:

| Что прислали | Тип | Как читается |
|---|---|---|
| `@name`, `t.me/name` | ✈️ `tg` | Telethon, нужен `TELEGRAM_API_ID` |
| `t.me/s/name` | 👀 `tgweb` | публичная витрина канала, **без** `api_id` |
| ссылка с `rss`/`feed`/`.xml` | 📡 `rss` | лента напрямую |
| любая другая ссылка | 🌐 `web` | автопоиск RSS, иначе разбор статей со страницы |

Телеграм-канал проверяется на доступность сразу при добавлении.

### Каналы без api_id

Если `TELEGRAM_API_ID` ещё не получен, `@name` автоматически понижается до
витрины `t.me/s/name` — той самой страницы, которую Telegram показывает в
браузере. Она отдаёт последние ~20 постов и не требует ни аккаунта, ни ключей.

Ограничения витрины: только открытые каналы, и только те, где владелец не
отключил предпросмотр (иначе бот скажет об этом прямо в списке источников).
Закрытые каналы и чаты читаются исключительно через Telethon.

Когда получите `api_id`, добавьте эти каналы заново как `@name` — они
переподключатся на полноценное чтение.

**Темы** — то, ради чего всё затевалось. Мастер из четырёх шагов:

| Шаг | Что вводится | Пример |
|---|---|---|
| 1 | название | `Утечки персональных данных в РФ` |
| 2 | описание — его читает модель | `Интересуют подтверждённые утечки баз российских компаний: кто пострадал, объём данных, реакция регулятора. Слухи и перепечатки — мимо.` |
| 3 | ключевые слова | `утечка, слив базы, персональные данные, Роскомнадзор, взлом*` |
| 4 | стоп-слова | `вебинар, курс, скидка, розыгрыш` |

Правила ключевых слов:

* `санкции` — по основе слова: поймает «санкций», «санкциям», «санкциями»;
* `утечк*` — совпадение по префиксу, для слов с беглой гласной («утечек»);
* `персональные данные` — фраза, слова ищутся подряд и тоже по основам, поэтому
  найдётся и «персональных данных»;
* **стоп-слова** отбрасывают пост, даже если ключевые слова совпали;
* шаг 3 можно пропустить (`-`) — тогда все посты рубрики пойдут на анализ модели:
  ничего не пропустите, но заплатите за каждый пост.

**Настройки рубрики** — интервал опроса (10 мин … 12 ч), порог релевантности
(40/55/70/85 %) и мгновенная отправка. Ниже порог — больше новостей и больше
шума; выше — тише, но растёт риск пропустить.

**Команды:** `/form` — шаблон формы, `/add` — принять форму, `/digest` — дайджест
за сутки, `/run` — проверить всё прямо сейчас, `/stats` — сколько отсеяно на
каждом шаге, `/bind` и `/unbind` — назначить или снять управляющую группу,
`/chatid` — ID чата и ваш собственный, `/help` — справка.

## Структура

```
run.py                     запуск бота, парсеров и планировщика в одном процессе
login_telegram.py          разовая авторизация Telethon
app/
  config.py                чтение .env
  pipeline.py              сбор → предфильтр → анализ → сохранение → публикация
  scheduler.py             APScheduler, по задаче на рубрику
  db/database.py           схема SQLite, миграции, три рубрики по умолчанию
  db/repo.py               все SQL-запросы
  parsers/tg.py            Telethon: чтение каналов и чатов
  parsers/web.py           RSS, автопоиск ленты, разбор HTML-статей
  analysis/prefilter.py    ключевые слова, стеммер, поиск фраз
  analysis/base.py         общий промпт и схема ответа для движков
  analysis/ollama.py       локальная модель
  analysis/claude.py       Claude через API
  analysis/llm.py          выбор движка
  bot/forms.py             разбор и применение формы пополнения
  bot/middlewares.py       доступ: личка, управляющая группа, чужие чаты
  bot/handlers/community.py  привязка группы и каналов, приём форм
  bot/                     остальные хендлеры, клавиатуры, FSM, тексты
```

Всё состояние — в одном файле `news_parser.sqlite3`: рубрики, источники, темы,
обработанные посты и их разборы, подписки. Обработанные посты хранятся и после
отсева — по ним считается статистика и на них же держится дедупликация.

## Заметки по эксплуатации

* **Первый опрос канала** берёт только 5 последних постов, дальше — до 30 за раз.
  Иначе первый запуск вывалил бы на вас всю историю.
* **Порог и стоп-слова — основные ручки.** Если новостей приходит слишком много,
  сначала добавьте стоп-слова, потом поднимайте порог.
* **FloodWait.** Telegram может попросить подождать при частом опросе многих
  каналов — источник помечается ошибкой и пропускается до следующего круга,
  остальные продолжают работать.
* **Стоимость.** Модель видит только посты, прошедшие предфильтр. На живом
  прогоне двух ИБ-лент из 30 постов до модели дошло 11.
* **Состояние в памяти.** FSM хранится в `MemoryStorage` — незаконченный ввод
  темы теряется при перезапуске. Для продакшена замените на Redis-хранилище
  aiogram.
